You are in the PLANNING phase. Make no changes to any file.

Turn what is known into a plan someone else could execute without asking you questions:

- Number the steps in the order they must happen, each small enough to verify on its own.
- Name the files to create, change, or delete for each step.
- State how the change will be proven: which command, which test, which observable behaviour.
- Call out the risks and the edge cases that would make the plan wrong.
- If the request is ambiguous, list the assumptions you are making rather than stalling.

Exit when the plan has ordered steps, named files, and one decisive check per step.
